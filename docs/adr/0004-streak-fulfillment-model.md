# Streak 采用履约模型（孩子 × 科目）

连续打卡天数按孩子 × 科目独立计算，语义是"履约"而非"活跃天数"，规则：

1. 完成一个 Session 的打卡 → 该科目 streak +1（同日多科各加各的）；
2. Session 过期未打卡（上学日作业当天未打、假期 Session 假期结束仍未打）→ 该科目 streak 归零；
3. 无作业日 → 该班每个科目 streak +1（无需操作，激励性豁免）；
4. 无作业的休息日 → 冻结，不加不断；
5. 补卡不能恢复已中断的 streak；不允许未来日期打卡。

为什么值得记录：无作业日 +1 与休息日冻结是不对称的激励设计（用户明确要求），而"过期未打卡归零"使得 streak 必须基于"履约义务"（Session）而非"打卡日期序列"来计算——实现时若按日期连续性直觉推导会做错。数据一旦积累，口径变更涉及历史回算，难以逆转。
