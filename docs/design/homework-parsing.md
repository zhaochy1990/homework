# 作业解析与确认流设计 v1

> 产出自 wayfinder ticket「Grilling: LLM 作业解析与确认流设计」。上游依据：`docs/research/004-deepseek-api.md`（DeepSeek 约束）、`docs/design/data-model.md`（010）、`docs/design/api-contract.md`（011）、`docs/adr/0007`（全局科目枚举）。
> Prompt 草案：`backend/internal/homework/parse/prompts/parse_v1.md`。

## 1. 流程总览

```
管理员粘贴老师原文
        │
        ▼
POST /classes/{classId}/homework/parse   ← 同步 LLM，30s 超时，不落库
        │
   ┌────┴─────────────────────────┐
   │ 成功                          │ 失败（超时 / 5xx / schema 不符 / 空结果）
   ▼                              ▼
草稿确认页（按科目分组）      错误提示 + [重试] [手动填写]
   │                              │            │
   │                              │ 重试（同模型同 prompt，temperature 0.3，30s）
   │                              │      │
   │                              │ 仍失败 └──▶ 手填页（多行文本框，单科目）
   ▼                              ▼            ▼
POST /classes/{classId}/homework  ← 单事务入库 + msgSecCheck
```

关键性质：**解析不落库、入库才落库**。管理员可以在确认页上改到满意为止，反复"重新解析"，库里始终什么都没有。

## 2. 输入与前置

| 输入 | 说明 |
|---|---|
| `classId` | 班级；须为 admin |
| `date` | `YYYY-MM-DD`（CST）。允许任意过去日期补录，**禁止未来日期**（400 `future_date_forbidden`） |
| `rawText` | 老师原文，管理员粘贴，原样保留 |
| `defaultSubject?` | 可选兜底科目：原文完全看不出科目时用它。UI 默认选中管理员当前浏览的科目 |

**科目取值域**：全局封闭枚举（ADR 0007），代码内唯一常量表，prompt 中逐字列出：

```
语文 / 数学 / 英语 / 物理 / 化学 / 生物 / 历史 / 地理 / 道法 / 科学 / 体育 / 艺术 / 其他
```

**已有 Session 探测**：解析端点对每个科目分组回填 `target`，让管理员在确认页就看见"这科已有作业、将追加"，而不是提交时才撞 409。

## 3. 解析请求

### 3.1 调用参数

| 参数 | 首轮 | 重试 |
|---|---|---|
| 模型 | 配置项 `DEEPSEEK_MODEL`（默认 `deepseek-flash`） | 同首轮（Q2） |
| temperature | `0` | `0.3`（Q1：温度 0 下同 prompt 重试会复现同一失败） |
| `max_tokens` | 2000 | 2000 |
| `response_format` | `{"type":"json_object"}` | 同 |
| 超时 | 30s | 30s |
| 自动重试 | **无**（不自动退避；重试由管理员点按钮触发） | — |

DeepSeek JSON mode 的硬性要求：**prompt 中必须出现 "json" 字样并给出格式示例**（004 §2.1），system prompt 已满足。请求时不带 `tools`/function calling。

### 3.2 Prompt 组织

- 位置：`backend/internal/homework/parse/prompts/parse_v1.md`，经 `go:embed` 嵌入，**文件头带版本号**；
- 结构：`# 角色` → `# 输出` → `# 字段规则` → `# 分类规则` → `# 示例`（3 个 few-shot）；
- system 放全部内容（前缀稳定 → 命中 DeepSeek 上下文硬盘缓存，004 §1.4）；user 只放 `rawText`，并附一句 `date` 对应的星期（帮助"周五前交"这类判断，但模型不解析日期，见下）；
- 日志记录 prompt 版本号，便于回溯源。

### 3.3 输出 schema

```jsonc
{
  "todos": [
    {
      "subject": "数学",              // 必填，封闭枚举之一
      "content": "口算天天练 P12",      // 必填，学生视角一句话，逐字保留教辅/页码引用
      "estimated_minutes": 15          // 必填（模型侧）；无法估算给 null
    }
  ],
  "unparsed": ["明天带一把彩笔"]         // 可为空数组
}
```

被**刻意剔除**的字段（004 草案中的）：`task_type`（无 UI 消费方）、`confidence`（改由确认页"全部条目都需过目"承担）、`count`（并入 `content` 文本）、`due_hint`（Session 已携带日期与截止；非当日事项走 `unparsed`）、`reason`（徒增 token 与漂移面）。`subject` 保留是因为我们**支持混科解析**。

`unparsed` 的定位：老师原文里**不是学生作业、但值得让家长看见**的信息（"明天带彩笔""家长检查并签字""周五前交"）。寒暄与通知（"收到请回复""@所有人"）既不入 `todos` 也不入 `unparsed`。

### 3.4 Go 侧严格校验

JSON mode 只保证"是合法 JSON"，不保证 schema（004 §2.1）。逐个分组校验，任一不符即整次解析判失败：

| 校验 | 不通过的处置 |
|---|---|
| 顶层是对象且含 `todos` 数组 | 失败 |
| `todos` 非空，**或** `unparsed` 非空（两者全空 = 解析失败，004 §4） | 失败 |
| 每条含非空 `subject` / `content` | 失败 |
| `subject` ∈ 全局枚举 | 归一到"其他"（不判失败——这是无害漂移，归一比打断用户更划算） |
| `estimated_minutes` 为 null 或正整数 | `≤0` 或非整数 → 置 null |
| `content` 去空白后非空、长度 ≤ 512（`todos.content` 列宽） | 超长截断并保留 |
| `unparsed` 为字符串数组 | 非数组 → 置空 |

`subject` 归一而 `content` 不宽容，是因为前者是**展示维度**（猜错了管理员一眼能改），后者是**信息本身**（改错了孩子就做错作业）。

### 3.5 失败分类

| 失败模式 | 检测 | 处置 |
|---|---|---|
| 网络错误 / 5xx / 429 | HTTP 状态 | 不自动重试；返回 502 `llm_unavailable` |
| 超时（30s） | context deadline | 返回 502 `llm_unavailable` |
| 截断 | `finish_reason=length` | 先按最后一个完整 `}` 截断修复一次；仍失败 → 422 `llm_parse_failed` |
| JSON 语法错误 | `json.Unmarshal` 失败 | 422 `llm_parse_failed` |
| JSON 合法但 schema 不符 | §3.4 | 422 `llm_parse_failed` |
| 内容安全拒绝 / 空回复 | 4xx + content_filter 错误码 | 422 `llm_parse_failed`，提示语不同 |
| 空结果 | `todos` 与 `unparsed` 全空 | 422 `llm_parse_failed` |

**统一由管理员点"重试"驱动**（不自动退避重试）：`temperature` 提到 0.3、同 prompt、同 30s。重试仍失败 → 引导进入手填页。第 4 级兜底永远是人的手，AI 不能成为发作业的单点故障（004 §4）。

失败样本落**结构化日志**（不建表）：`prompt_version`、`model`、耗时、失败类型、`rawText` 摘要、原始响应摘要。v1 不做 prompt 评测集，需要时从日志捞。

## 4. 确认页

### 4.1 结构

```
┌─────────────────────────────────────┐
│ 2026-09-22 周一 · 作业确认            │
├─────────────────────────────────────┤
│ ▸ 语文            〔新建〕   ≈20 分钟 │
│   ⋮≡  抄写第5课生词三遍          [×] │
│       [＋ 添加待办]                   │
├─────────────────────────────────────┤
│ ▸ 数学        〔追加 · 已有 3 条〕    │
│   ⋮≡  黄冈同步 P23-24 做完对答案  [×] │
│       口算天天练 P12              [×] │
│       [＋ 添加待办]                   │
├─────────────────────────────────────┤
│ 老师还提到（老师原话，家长可见）       │
│ ┌─────────────────────────────────┐ │
│ │ 明天带一把彩笔                    │ │
│ │ 家长检查并签字                    │ │
│ └─────────────────────────────────┘ │
├─────────────────────────────────────┤
│ 原文 ▸（可展开查看 rawText 全文）     │
├─────────────────────────────────────┤
│   [放弃]      [重新解析]   [确认入库] │
└─────────────────────────────────────┘
```

### 4.2 每条待办的操作

| 操作 | 说明 |
|---|---|
| 改文本 | 行内编辑 `content` |
| 改时长 | 行内编辑 `estimated_minutes`（可清空 → NULL） |
| 删条目 | `[×]`，直接删（未入库，无需二次确认） |
| 加条目 | `[＋ 添加待办]`，新增行，科目随所在分组 |
| 调顺序 | 拖拽（`⋮≡`）；同时支持上/下移按钮，避免拖拽在低端机上的手感问题 |
| 改科目 | 把一条**移动到另一个科目分组**（分组下拉）。混科解析最常见的错误就是归属判断错 |

### 4.3 **不做**的（Q4）

**合并两条**与**拆分一条**。两者都能用"增删改"等价完成（拆 = 加两条 + 删原条；并 = 改一条的文本 + 删另一条），不是能力缺口只是操作步数。为它们引入多选态、拖拽合并、拆分弹窗，是这一页复杂度最大的一笔投入，而使用频率极低。纯前端能力，将来要加不触后端。

### 4.4 三个出口

| 按钮 | 语义 |
|---|---|
| **重新解析** | 用当前 `rawText` 重跑一次，**覆盖全部草稿**（含已有 Session 的探测结果与"老师还提到"）；草稿非空时二次确认 |
| **放弃** | 直接返回发作业页，不入库（解析结果本来就没落过库） |
| **确认入库** | 单事务提交，见 §5 |

## 5. 入库

### 5.1 端点

`POST /classes/{classId}/homework`，请求体：

```jsonc
{
  "date": "2026-09-22",
  "rawText": "今天作业：……",           // 原样保留，审计与追溯用
  "groups": [
    {
      "subject": "语文",
      "todos": [{"content": "抄写第5课生词三遍", "estimatedMinutes": 20}],
      "notes": "明天带一把彩笔\n家长检查并签字"
    },
    {
      "subject": "数学",
      "todos": [{"content": "黄冈同步 P23-24 做完对答案", "estimatedMinutes": null}]
    }
  ]
}
```

### 5.2 事务步骤

1. **内容安全**（Q7=a）：把 `rawText` 与全部 `content`、`notes` 拼接后调 `msgSecCheck`（同步；超 2500 字按片切分多次调用）。命中 → 422 `content_blocked`，返回命中 label，**整单拒绝**（msgSecCheck 不返回位置，无法定位到具体条目）。
   *解析端点不检测* —— 解析不入库、不展示给他人；检测只发生在这一个入库隘口，手填路径自动获得同样的保护。
2. **Session 判定**：每个分组按上学日历判定 `kind`（上学日含调休补班 → `day`；休息日 → 自动定位所在连续休息段 → `holiday`，`start_date`/`end_date`/`holiday_name` 自动算）。
3. **冲突校验**（全部在事务内、写之前一次做完）：
   - 该班该科该日期（或该休息段）已有 Session → **追加**，往它里面加 todo（`target=append` 的常规路径）；
   - 若同时命中"无作业日"标记 → 409 `no_homework_day_conflict`；
   - 并发下另一个管理员刚发了同科作业 → **整单 409 `duplicate_session`，响应体指明冲突的科目**，不落任何一半。
4. **写入**：新建的 Session + 全部 Todos（`sort_order` 按确认页最终顺序）+ `notes` + `rawText`，一个事务提交。
5. **事后**：追加进已有 Session 的 todo 对已打卡孩子显示"新增未完成"，**不影响打卡与 streak**（数据模型影响矩阵 #2）。

### 5.3 追加解析（Q6）

老师说"补充一条：数学再加一页口算"是高真实频次场景。没有追加能力时，管理员在入库这一步撞 409 就走进死胡同，只能退出去逐条手加。

因此：**解析端点探测已有 Session 并在确认页标注 `target=append`**，管理员看到的是"数学〔追加 · 已有 3 条〕"；确认页同时展示已有条目（灰、只读）与新增条目（可编辑），提交时只追加新增的。

确认页不自动去重 —— 管理员自己看得见已有条目，重复了删掉即可，比"聪明的去重"更可预期。

## 6. 降级手填页（Q4/Q5）

解析两轮都失败后进入。**单科目**，因为多行文本框没有分组能力。

```
┌─────────────────────────────────────┐
│ AI 没能读懂这段作业，请手动整理        │
├─────────────────────────────────────┤
│ 科目： [数学 ▾]        （默认选中当前科目）│
├─────────────────────────────────────┤
│ 一行一条待办：                        │
│ ┌─────────────────────────────────┐ │
│ │ 黄冈同步 P23-24 做完对答案        │ │
│ │ 口算天天练 P12                   │ │
│ │                                 │ │
│ └─────────────────────────────────┘ │
├─────────────────────────────────────┤
│ 老师原文（照抄用，会一起存下来）       │
│ ┌─────────────────────────────────┐ │
│ │ 今天作业：1.数学黄冈同步P23-24…… │ │
│ └─────────────────────────────────┘ │
├─────────────────────────────────────┤
│            [返回重试]    [确认入库]   │
└─────────────────────────────────────┘
```

- 文本框内容按行切成待办（去空行、首尾空白），`estimated_minutes` 一律 NULL；
- 原文区域只读展示 `rawText`，它与手填的待办一起入库；
- 一段文本只能填一个科目，含多科请分两次录入（页面明说这条规则）；
- 手填路径走**同一个** `POST /classes/{classId}/homework`，因此内容安全、追加、冲突规则全部一致。

## 7. 展示口径（Q3）

| 位置 | 展示 |
|---|---|
| 作业页 · 每条待办 | **只显示内容本身**，不显示条目级时长——逐条展示估算值是伪装精确，且破坏勾选列表的扫读（013 定稿） |
| 作业页 · 每个科目分组标题 | 该 Session 已估条目之和，如 `≈35 分钟`；一条都没估则不显示 |
| 作业页 · 底部 | `notes` 以"老师还提到"区块展示，与待办列表视觉分离 |
| 打卡卡片 | **不含** `estimated_minutes` 与 `notes`。卡片是成绩单，不是通知栏 |

`estimated_minutes` 可空（模型没给、或走手填路径）；`0` 与负数视为非法，写入前归一为 NULL。合计时跳过 NULL 条目。

## 8. 数据模型回填

```go
type Todo struct {
    ID               string `gorm:"primaryKey;size:26"` // ULID
    SessionID        uint64 `gorm:"index"`
    Content          string `gorm:"size:512"`
    EstimatedMinutes *int   // 模型估算的完成时长；NULL = 未估（手填路径一律 NULL）
    SortOrder        int
    CreatedAt        time.Time
}

type HomeworkSession struct {
    // …既有字段…
    RawText string `gorm:"type:text"` // 管理员粘贴的原文，原样保留
    Notes   string `gorm:"type:text"` // "老师还提到"：unparsed 拍平后的可编辑备注
}
```

## 9. API 契约回填

- `POST /classes/{classId}/homework/parse` 入参由 `{subject, date, rawText}` 改为 `{date, rawText, defaultSubject?}`；返回改为按科目分组的草稿，每组带 `target: new|append`、`sessionId?`、`existingTodos?`、`kind`、`startDate?`/`endDate?`/`holidayName?`、`todos`、`notes`；
- `POST /classes/{classId}/homework` 入参改为 `{date, rawText, groups: [{subject, todos, notes?}]}`，单事务；
- 新增错误码 `422 content_blocked`（作业原文或待办命中内容安全）；
- `GET /children/{childId}/homework` 与 `GET /classes/{classId}/homework` 的 todo 增加 `estimatedMinutes`，Session 增加 `notes`。

## 10. 实施备忘与待验证

- **待验证**（本会话网络受限，接入前须核实）：
  - `deepseek-flash` / `deepseek-v4-pro` 的价格（模型名已实测，004 §1.1）；
  - DeepSeek 是否已提供 `json_schema` strict 模式（若有，§3.4 的手工校验可减负，但保留兜底）；
  - `msgSecCheck` 的单次文本长度上限与 QPS 配额（002 已标记待验证），影响 §5.2 的分片阈值；
  - 温度 0.3 的重试是否足以避开复现 —— 上线后用日志里的失败样本回归验证。
- **并发**：同一管理员连点"确认入库"用前端按钮 disable + 后端唯一约束双保险。
- **时区**：`date` 一律 CST 日历日；`date` 对应的星期由后端算好带给 prompt，模型不做日期运算（004 §3.1 坑 6）。
- **成本**：system prompt 固定前缀命中 DeepSeek 上下文缓存，单次解析成本按"每个班每天 < 1 分钱"量级（004 §1.4），不是设计约束。
